## Rules
Nodes
- Exactly one `trigger` per workflow: it has no incoming edges.
- `end` nodes have no outgoing edges. Every path must finish at an `end` node. Use several ends for different outcomes (for example "Login allowed" and "Login rejected").
- `action` nodes have exactly one outgoing edge. `condition` nodes have two or more.
- Only `condition` nodes may have several outgoing edges. Branches may merge into shared downstream nodes.
- No cycles. Model retries or loops as a single action step, or end the flow with a note.
- Every node must be reachable from the trigger and must lead to an end.
- IDs must be unique within a workflow; edge `source`/`target` must reference existing node ids.

Edges
- An edge leaving a `condition` node needs either:
  - a `condition` object (`variable`, `operator`, and `value` where required), or
  - `"fallback": true` (the "else" route). Use at most one fallback per condition, with no `condition` object.
- Edges from a condition are evaluated in ascending `priority` (0, 1, 2…); the first match wins. Put the fallback last.
- Edges leaving non-condition nodes: `"fallback": false`, `"priority": 0`, no `condition`.
- Give every condition edge a short `label`, such as "valid" or "disabled".
- Operators: `equals`, `notEquals`, `greaterThan`, `lessThan`, `isTrue`, `isFalse`.
  - `isTrue` and `isFalse` take no `value`.
  - The others require `value`, which must be a string, number or boolean.
- `condition.variable` must be a simple identifier (camelCase) that exists as a key in the `inputs` of every use case of that workflow.

Use cases
- All use cases of a workflow share one diagram. Do not duplicate nodes.
- Each use case's `inputs` must contain EVERY variable used by any condition in that workflow, with values chosen so the simulation reaches a different end node or branch.
- Check each use case by hand: walk the graph from the trigger using its inputs and confirm it reaches an end without hitting an unmatched condition.

Layout
- Flow runs left to right. Set x = column × 300 (start at 0) and y = row × 140. Branches go in different rows. The user will run Auto Layout in the app, so approximate is fine.

Quality
- Titles are short; phrase condition nodes as questions ("Account active?").
- No secrets, tokens or personal data in the output.
- Use only the JSON types shown (no comments, no trailing commas).
